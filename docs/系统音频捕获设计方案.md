# 系统音频捕获设计方案

## 目标

为 CapsWriter-Offline 增加系统音频（扬声器输出）转文字功能。用户可通过 Tab+F1 切换音频源，在麦克风输入和系统音频捕获之间切换。

## 需求要点

- 捕获系统扬声器输出的音频（WASAPI Loopback）
- 通过 Tab+F1 切换捕获模式
- 支持在多个输出设备间选择捕获源（托盘菜单）
- 捕获后的音频走与麦克风相同的识别管线（热词、LLM、上屏）
- 灵动岛显示状态文字相应变化

## UI 提示

切换音频源时只替换灵动岛 IDLE 状态的文字，ARMED/SPEAKING 状态不变：

| 状态 | 麦克风 | 系统音频 |
|------|--------|----------|
| IDLE（空闲） | "就绪" | "系统音频监听中" |
| ARMED（按下键） | "可以说话了" | 不变 |
| SPEAKING（录音中） | "正在听" | 不变 |

## 技术选型

### WASAPI Loopback 捕获方案

**推荐方案：`comtypes` 直接调用 Windows WASAPI COM 接口**

不使用 `soundcard` 库（社区维护状态不确定），改用 `comtypes` 直接调用原生 WASAPI COM 接口（`IMMDeviceEnumerator` → `IAudioClient` → `IAudioCaptureClient`），对 Windows 版本的兼容性更可控。

| 对比项 | soundcard | comtypes 直连 WASAPI |
|--------|-----------|---------------------|
| 底层 API | WASAPI COM（间接） | WASAPI COM（直接） |
| Loopback 支持 | 原生支持 | 原生支持 |
| 设备枚举 | `include_loopback=True` | `IMMDeviceEnumerator::EnumAudioEndpoints` |
| 数据格式 | numpy float32 | numpy float32 |
| 安装 | `uv add soundcard` | `uv add comtypes` |
| 维护状态 | 社区维护，更新缓慢 | 微软官方 COM 接口，稳定 |

`comtypes` 是纯 Python COM 桥接包，无需编译。WASAPI 捕获逻辑封装为独立模块 `core/client/audio/wasapi_loopback.py`。

### 快捷键方案

**Tab + F1 组合键：**

避免双击检测带来的 CapsLock 延迟补键冲突，也不与常见系统/应用快捷键冲突。

| 手势 | 行为 |
|------|------|
| 按 Tab 的同时按 F1 | 切换音频源（麦克风 ↔ 系统音频） |

实现：`shortcut_manager.py` 跟踪 Tab 键状态，`on_press` 检测到 F1 时检查 Tab 是否也按着。

### 源切换行为

Tab+F1 或托盘菜单切换设备时：

1. 当前录音缓冲立刻 flush + 送入 Server（与松开键行为一致）
2. 清空缓冲，切换到新源
3. 用 `threading.Event` 控制线程启停，避免数据交错

### WASAPI 线程空闲休眠

WASAPI 捕获线程在未录音时通过 `threading.Event.wait()` 休眠，不空转 CPU。仅当 `state.recording == True` 时才从缓冲区拉取数据：

```python
while running:
    event.wait()              # 未录音时阻塞
    if not running: break
    # 从 IAudioCaptureClient 拉数据
    # 送入 asyncio queue
```

### 托盘菜单设备切换

托盘右键菜单增加二级菜单：

```
切换输出设备 →
  ├─ ● 扬声器 (Realtek Audio)
  ├─ ○ 耳机 (HyperX Cloud II)
  └─ ○ DELL S2722QC
```

- 启动时通过 WASAPI `IMMDeviceEnumerator` 枚举所有输出设备并缓存
- 选中项前面显示标记
- 插拔设备需重启客户端（不提供实时刷新按钮，避免复杂度和性能开销）
- 切换时重建 WASAPI 捕获客户端

## 安全注意事项

1. **线程安全**：WASAPI 捕获在独立线程运行，通过 `threading.Event` 控制停止。数据通过 `asyncio.run_coroutine_threadsafe` 送入主循环队列。
2. **COM 初始化**：捕获线程需调用 `comtypes.CoInitialize()` / `CoUninitialize()`。
3. **非主线程 UI 操作**：避免在 pystray / Timer 线程中调用 `toast()`（tkinter 非线程安全）。
4. **缓存化**：所有 WASAPI API 仅在初始化时调用一次，运行时只读缓存。

## 测试要点

1. 启动后托盘菜单显示所有可捕获的输出设备
2. Tab+F1 切换模式，灵动岛文字变化
3. 长按录音键从系统音频源录音
4. 松开后识别结果正常上屏（热词、LLM 均生效）
5. 切换回麦克风模式，长按恢复麦克风录音
6. 托盘菜单切换不同输出设备
7. 切换源时当前录音立即结束并输出，接入新源
8. 无 loopback 设备时 Tab+F1 提示不可用
9. **录音中按 Tab+F1**：正在长按录音时切换源，当前录音 flush 上屏，新源正常接管
10. **快速连按 Tab+F1**：短时间内多次切换，状态机不卡死
11. **切换设备后该设备被拔掉**：切换到的输出设备被拔出，再次长按录音不崩溃、不静默失败
12. **系统音频完全静音**：无程序发声时录音，Server 返回空/超时，客户端无异常
13. **`system_audio_enabled = False`**：Tab+F1 不响应，托盘不显示切换菜单，不影响正常 mic
14. **空闲 CPU 开销**：WASAPI 线程在未录音时休眠，不空转（用 `threading.Event.wait()`）
