# 系统音频捕获设计方案

## 目标

为 CapsWriter-Offline 增加系统音频（扬声器输出）转文字功能。用户可通过双击 CapsLock 切换音频源，在麦克风输入和系统音频捕获之间切换。

## 需求要点

- 捕获系统扬声器输出的音频（WASAPI Loopback）
- 通过双击 CapsLock 切换捕获模式
- 支持在多个输出设备间选择捕获源
- 捕获后的音频走与麦克风相同的识别管线（热词、LLM、上屏）
- 灵动岛显示状态文字相应变化

## 技术选型

### WASAPI Loopback 捕获方案

**推荐方案：`soundcard` 库**

`soundcard` 底层通过 `comtypes` 直接调用 Windows WASAPI COM 接口，不走 PortAudio。相比 `sounddevice` 的优势：

| 对比项 | sounddevice | soundcard |
|--------|-------------|-----------|
| 底层 API | PortAudio | WASAPI COM 直连 |
| Loopback 支持 | 依赖 PortAudio 版本和驱动 | 原生支持 |
| 设备枚举 | 不枚举回环设备 | `include_loopback=True` 直接获取 |
| 数据格式 | numpy float32 | numpy float32 |
| 安装 | 已有依赖 | `uv add soundcard` |

**为什么不直接用 PortAudio/sounddevice：**
在部分 Windows 系统上（如用户的环境），PortAudio 不将 WASAPI Loopback 设备枚举为输入设备，导致无法捕获。`soundcard` 通过 COM 直连 WASAPI，无此问题。

### 快捷键方案

**双击 CapsLock 检测：**

CapsLock 当前已有长按录音功能，需要区分三种手势：

| 手势 | 行为 |
|------|------|
| 短按 (< 0.3s) 单次 | 切换 CapsLock 开关（补发按键） |
| 长按 (≥ 0.3s) | 当前音频源录音 |
| 短按 × 2 (间隔 < 0.4s) | 切换音频源（麦克风 ↔ 系统音频） |

双击检测在 `ShortcutEventHandler._handle_short_press()` 中实现：短按时延迟补发按键，在延迟窗口内检测第二次短按则判定为双击。

## 实现架构

```
                    ┌──────────────────────────┐
                    │   AudioStreamManager     │
                    │  ┌────────────────────┐   │
  Mic InputStream ──┤  │  mic callback       │   │
  (sounddevice)    │  │  (state.recording   │   │
                    │  │   && !system_audio) │   │
                    │  └────────────────────┘   │
                    │  ┌────────────────────┐   │
  System Audio ─────┤  │  loopback thread    │   │
  (soundcard)       │  │  (state.recording   │   │
                    │  │   && system_audio)  │   │
                    │  └────────────────────┘   │
                    └──────────┬───────────────┘
                               │ queue_in
                               ▼
                    ┌──────────────────────────┐
                    │     AudioRecorder        │
                    │  (source='mic'/'system') │
                    └──────────┬───────────────┘
                               │ WebSocket
                               ▼
                    ┌──────────────────────────┐
                    │       Server             │
                    │  (type='mic'/'system')   │
                    └──────────────────────────┘
```

```python

set_system_audio_mode(active: bool)       # 切换捕获模式
switch_loopback_device(device_idx: int)   # 切换设备
list_loopback_devices_safe() -> list[dict]  # 获取缓存设备列表
ensure_loopback_cache()                   # 惰性初始化缓存
```

## 安全注意事项

1. **线程安全**：`soundcard` 捕获在独立线程运行，通过 `threading.Event` 控制停止。数据通过 `asyncio.run_coroutine_threadsafe` 送入主循环队列。
2. **COM 初始化**：捕获线程需调用 `comtypes.CoInitialize()` / `CoUninitialize()`。
3. **非主线程 UI 操作**：避免在 pystray / Timer 线程中调用 `toast()`（tkinter 非线程安全）。
4. **缓存化**：所有 `soundcard` / `sounddevice` API 仅在初始化时调用一次，运行时只读缓存。

## 依赖

```
uv add soundcard
```

`soundcard` 会自动安装 `comtypes` 依赖（纯 Python COM 实现，无需编译）。

## 用户配置

```python
# config_client.py
system_audio_enabled = True              # 启用功能
system_audio_loopback_device = None      # 指定设备名关键词
system_audio_double_tap_interval = 0.4   # 双击检测间隔(秒)
```

## 测试要点

1. 启动后托盘菜单显示所有可捕获的输出设备
2. 双击 CapsLock 切换模式，灵动岛文字变化
3. 长按 CapsLock 从系统音频源录音
4. 松开后识别结果正常上屏（热词、LLM 均生效）
5. 双击切换回麦克风模式，长按恢复麦克风录音
6. 托盘菜单切换不同输出设备
7. 无 loopback 设备时双击提示不可用
