# 绿色免安装版打包说明

把 CapsWriter-Offline 打包成一个「双击即用」的文件夹：内置便携式 Python 运行时，
目标机器**不需要**安装 Python、uv 或任何依赖。

> 与 v3.0 的 UV 双包分发（`uv tool install capswriter-client`）并行存在，
> 面向「不想碰命令行、只想双击运行」的用户。

---

## 一、快速开始

在项目根目录（已激活 `c` 环境 / 有 PyInstaller 的环境）执行：

```bat
python build_portable.py
```

约 2~4 分钟后得到：

```
dist/CapsWriter-Offline/
├── CapsWriter-Offline.exe    ← 双击这个（启动器）
├── start_server.exe          ← 服务端，由启动器拉起
├── start_client.exe          ← 客户端，由启动器拉起
├── internal/                 ← 便携式 Python 运行时 + 全部第三方依赖
├── core/                     ← 核心源码，保留为 .py，用户可改
├── LLM/                      ← LLM 角色，可增删 .py
├── assets/icon.ico           ← 托盘 / 窗口图标
├── config_client.py          ← 客户端配置
├── config_server.py          ← 服务端配置
├── hot.txt  hot-rule.txt  hot-server.txt
├── models/                   ← 语音模型（默认是目录链接）
├── logs/                     ← 运行日志
├── 启动 CapsWriter.bat        ← 启动器不可用时的兜底方案
└── 打包说明.txt
```

用户侧只需要：**双击 `CapsWriter-Offline.exe`**。

## 二、命令行参数

| 参数 | 说明 |
|------|------|
| `--models junction` | **默认**。`dist/CapsWriter-Offline/models` 建目录链接指向项目 `models/`，不复制 943 MB。仅本机自用。 |
| `--models copy` | 把 `models/` 整个复制进发行包（+943 MB）。可直接拷给别人。 |
| `--models none` | 发行包不含模型，由用户自行放置。 |
| `--clean` | 构建前先删掉 `build/` 与 `dist/`。 |
| `--no-build` | 跳过 PyInstaller，只做产物整理（调试用）。 |
| `--with-node` | 额外打包 `node.exe` + `native-recorder-nodejs` 到 `runtime/`（系统音频捕获用，约 80 MB）。 |

## 三、启动器做了什么

`launcher.py` 编译成 `CapsWriter-Offline.exe`，是一个 Tk 进度窗口：

1. 检查 `127.0.0.1:6016` 是否已被占用；已占用则认为服务端在运行，跳过第 2 步；
2. 以隐藏控制台方式拉起 `start_server.exe`，把它的 stdout 实时抓进窗口日志区；
3. 轮询端口直到可连接；
4. 拉起 `start_client.exe`；
5. 3 秒倒计时后自动关闭窗口，服务端与客户端继续在后台运行。

### 为什么「端口可连接」就等于「服务就绪」

`core/server/app.py` 的 `CapsWriterServer.start()` 顺序是：

```
register_signal → tray_manager.start() → _print_banner()
→ process_manager.start()      # 阻塞轮询，直到子进程把模型全部加载完
→ socket_manager.start()       # 这一步才 bind 端口
```

**端口 bind 发生在模型加载完成之后**，所以 TCP 能连上端口就说明 ASR 服务已经可用。

### 失败时的表现

服务端提前退出（最常见原因：`models/` 缺文件）时，窗口会：
- 停在失败页，把捕获到的服务端输出（含 `check_model()` 给出的缺失文件与下载链接）打进日志区；
- 提供「打开日志目录」「打开模型下载页」两个按钮。

## 四、打包细节

`build.spec` 要点：

- **三个入口**共用一次 `COLLECT`：`start_server.py`（`console=True`）、
  `start_client.py`（`console=False`）、`launcher.py`（`console=False`）。
- **私有模块外置**：`core` / `LLM` / `config_client` / `config_server` 从 `Analysis.pure`
  中剔除，改为把源码目录原样复制到发行根目录，由 `build_hook.py` 在运行时把
  `<exe目录>` 与 `<exe目录>/internal` 插入 `sys.path`。
  好处：用户改配置 / 改热词 / 加 LLM 角色 / 看源码都无需重新打包。
- **排除体积凶手**：`torch`、`transformers`、`funasr`、`onnxruntime_providers_cuda`、
  系统 CUDA DLL、`numba` + `llvmlite`（约 130 MB，只有不被任何运行时模块 import 的
  `core/client/hotword/hotword_standalone.py` 用到）。
- **保留 `DirectML.dll`**（`internal/onnxruntime/capi/`），onnxruntime-directml 需要它。
- **`upx=False`**（本机未安装 UPX；开启也可能触发杀毒误报）。

> ⚠️ **不要**在 `excludes` 里写 `distutils` / `wheel` / `packaging` 等 setuptools
> 的 vendored 模块，PyInstaller 的 pre-safe-import 钩子会给它们建别名，排除后会直接抛
> `ValueError: Target module "xxx" already imported as "ExcludedModule('xxx',)"`。

### 依赖的可移植性补丁

打包版对两处外部依赖做了「可移植解析」，优先级为
**环境变量 → 发行包内置路径 → 旧硬编码路径兜底**：

| 依赖 | 环境变量 | 发行包内置路径 |
|------|----------|----------------|
| `node.exe` | `CAPSWRITER_NODE` | `runtime/node/node.exe` |
| `native-recorder-nodejs` | `CAPSWRITER_NATIVE_RECORDER` | `runtime/node_modules/native-recorder-nodejs` |

（见 `core/client/audio/wasapi_loopback.py`）
`--with-node` 会把这两样一并打进发行包；不加该参数时，会回退到系统已安装的
`node` 与开发机上的 OpenCode 路径。

`ffmpeg` 仍是外部依赖：检测到就用 mp3 压缩保存录音，否则存 wav。

## 五、分发到别的机器

| 场景 | 做法 |
|------|------|
| 同一台机器 | `--models junction` 即可，体积约 260 MB。 |
| 拷给别人（对方有模型） | 用 `--models none` 构建，让对方把模型放进 `models/`。 |
| 拷给别人（开箱即用） | 用 `--models copy` 构建，整个文件夹压缩后约 400~500 MB。 |
| 对方没有 Node / 想用系统音频捕获 | 加 `--with-node`。 |

注意：`junction` 是 NTFS 目录链接，压缩 / 复制到 U 盘或别的机器时会失效，
必须换成 `--models copy` 或 `--models none`。

## 六、验证产物

项目根目录留有几个临时验证脚本（可直接复用）：

```bat
:: 只测服务端：拉起 start_server.exe 并等端口就绪
python tmp_test_dist.py

:: 端到端：server + client，观察 30s 并打印双端日志
python tmp_test_client.py

:: 完整启动器：观察窗口、截图、端口、子进程、自动关闭
python tmp_test_launcher.py

:: 静态检查：产物的 PYZ 与数据目录里是否收了关键模块
python tmp_check_archive.py
```

预期：服务端约 8~15 秒（CPU 推理）后端口就绪，日志出现
`模型文件检查通过` 与 `开始服务`；客户端日志出现
`WebSocket 建立成功`、`托盘图标已启用`。

> 端口探测用的是裸 TCP 连接，服务端会打印几条
> `websockets ... InvalidMessage: did not receive a valid HTTP request`，
> 这是正常噪音，不是故障。

## 七、常见问题

**Q：启动器闪一下就没了？**
看 `logs/launcher.log`；若窗口弹出又消失，是启动流程走完了（正常，会自动关闭）。

**Q：提示缺少模型？**
把模型解压到 `models/` 下，目录结构见 `config_server.py` 的 `ModelPaths`。
下载页见 `ModelPaths` 同文件的 `ModelDownloadLinks.models_page`。

**Q：想看到服务端完整日志？**
直接双击 `start_server.exe`（带控制台），或看 `logs/server_latest.log`。

**Q：inno setup 安装包？**
本项目暂不提供；如需要可在 `dist/CapsWriter-Offline/` 基础上用 Inno Setup
打包，注意把 `models/` 的 junction 换成实体目录。
